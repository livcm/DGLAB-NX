# 文档约定

## 按读者分层

| 文档 | 读者 | 内容 |
| --- | --- | --- |
| 根 README | 用户 | 简介、安装、操作、限制、排查和许可 |
| docs/*.md、工具文档 | 开发者与 Agent | 设计原因、技术依据、实机结论、版本限制、验证入口 |
| 根 AGENTS | Agent | 跨组件架构约束与工作流程 |
| 组件 AGENTS | Agent | 局部约束，通用规则链接到根文件 |

构建、发布、测试与专题索引统一在 [development.md](development.md)。
技术文档先给当前结论，再写依据、限制与待验证项；规则、设计选择、协议事实和实机观察分清。

## 内容取舍

- 代码/测试能直接说明的接口形状、实现步骤、常量、用例枚举不重复维护，留下入口即可。
- 保留代码无法说明的原因、平台限制、外部来源、适用版本、实机证据与未验证事项，压缩表达。
- 临时实验过程、日志全文、已被替代的方案由 Git 历史保留，不继续堆积原文。
  [history.md](history.md) 只保留代码仍引用的历史节点及指向现行结论的索引。
- 同一事实放在最合适的专题，其它文档只留必要摘要和链接；AGENTS 不承载研究流水账。
- 冲突先查代码、测试、实机记录；不靠文字改写补事实，不把静态分析或主机测试写成实机验证。

## 整理检查

检查强制规则是否完整、独有证据/版本/来源是否保留、当前与历史状态是否区分，
并检查链接、锚点、源码引用和 diff。不改第三方文档，不混入代码或配置改动。
2026-09-17 的审计过程与后续迭代原文可从 Git 历史查阅。
