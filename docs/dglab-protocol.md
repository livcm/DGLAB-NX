# Coyote V3 协议

本项目支持郊狼 3.0（Coyote V3），V2 未实现。蓝牙 Coyote V2/V3 与
[Socket V3/V4](dglab-socket.md) 是独立协议线，版本没有对应关系。

BLE 会话已接上协议层，扫描、连接、GATT 与 BF/B0 写入已实机跑通；依赖补丁，回读不可得，
按开环设计。WebSocket 只复用波形编解码，不使用 BLE 会话节奏，详见 [BLE 验证](ble-poc.md)。

## 官方来源与实现入口

- [官方蓝牙协议仓库](https://github.com/dungeonlab-open/dglab-bluetooth-protocol)，
  已记录参考 commit `0155a23cfc123d1243b96482ea475d147573ce8f`（2026-06-11）。
- 对应资料：`coyote/README.md`、`coyote/v3/README.md`；协议变更前按
  [sysmodule 规则](../sysmodule/AGENTS.md#官方协议参考与实现) 重新核对设备/版本。
- `sysmodule/source/protocol/` 与对应 headers：编解码、强度状态机、100ms 会话层，
  均无 libnx/HOS 依赖；主机验证入口 `make -C tests/protocol`。
- 字节布局、频率换算、UUID、范围与具体状态机以实现和测试为准；传输不另推导 UUID。

## 协议边界

| 指令 | 需要记住的语义 |
| --- | --- |
| B0 | 两通道强度与四组波形；每组 25ms。某通道任一频率/波形强度越界，就丢弃该通道整组数据；强度设定值越界按 0 处理 |
| BF | A/B 各自的通道强度上限及平衡参数；上限是设备天花板，与用户强度不同。越界不修改当前值；立即生效、无回包，官方要求重连重写 |
| B1 | 强度变化通知；B0 引起的变化带对应序列号，拨轮等其它来源为 0；Switch 当前收不到 |

官方 B1 例子有三条边界：强度未变（如 0→0）不回；序列号 0 的 B0 可以改强度但不要求回应；
拨轮变化的序列号 0 不受这条规则影响。拨轮实验需要有效波形在播，手机实测也是有输出时才改强度。
电量的 ATT Read Response 与 `0x150B` 通知是不同通路，不能用读电量后的通知数量判断订阅是否成功。
BE 已被官方弃用，本项目不实现。

协议层支持等待非零序列号 B1 后再写强度，也支持不等待反馈；开环 BLE 不依赖设备确认。
状态机的请求记账不能冒充设备实际值。

### 波形、强度与上限

有效波形是输出前提，通道强度决定幅度，上限限制强度；A/B 各有自己的强度和上限。
上限或强度为 0 时没有幅度输出，但波形仍可播放。
手机实测（2026-09-26）上限/强度均 0 时开输出灯仍闪；Switch 正式会话于 2026-09-27
确认强度 0 时默认波形使灯闪。全零波形的频率 0 越界，设备丢弃整通道，增加强度也无效。
灯闪是观察判据，不能代替真实强度反馈或可感输出验证。

### 配对与设备绑定

2026-09-25 iOS 对照：默认连接不要求 bonding；App「设备绑定」才触发配对并保留系统记录。
未绑定时取消配对仍可控制；已绑定时取消则被 App 拒绝。
同日 Switch 对照：有绑定信息时仍能连接，但设备忽略控制写入；无绑定信息时可控制，
两种状态都无回包。因此控制实验前必须关闭「设备绑定」或重置设备。
优先不配对；已有配对探测按收到请求即取消设计，不能将设备绑到 Switch。

## 实现选择与官方资料冲突

1. 官方示例按通道维护序列号，但 B0/B1 只有一个包级字段；本项目共用计数器和闸门，
   A/B 变化合入一包，主机测试固定此选择。
2. `coyote/README.md` 写 650ms→204，V3 算法得到 205；采用 V3 算法，设备侧仍待确认。
3. 不足四槽不用频率 0 补齐（会使整个通道失效），而沿用最后频率、波形强度 0，保持数据有效。
4. tick 迟到不补发、循环对齐包边界、绝对归零覆盖未发送累积值、累积值钳制 ±200，
   均为项目策略，不是协议要求。

DG-LAB 使用基础 UUID 拼接私有 16-bit 号，不能按 SIG 标准服务名称推断用途。
实机 GATT 与广播是两回事：早期手机报告广播 `0x180C`，后续 Switch AD 实测未带服务 UUID，
不能据 GATT UUID 假定 UUID 过滤可发现设备，详见 [固件研究](ble-re.md#扫描与-gatt)。

## 验证边界

主机测试已有官方报文逐字节比对及编解码、状态机、会话验证，具体用例见 `tests/protocol/`。
Switch 输出及灯闪证据见 BLE 验证；连接归 btm、服务层不暴露回读的静态依据见
[连接所有权](ble-re.md#连接所有权在服务层是封的)。

仍待实机确认：BF 断电保存、A/B 上限钳制的边界、650ms 换算、频率 0 空闲与官方强度 101
空闲是否等价、100ms 调度抖动。B1/电量/读值按现有服务层不可得处理，不列为待打通功能。
正式 BLE_* 已存在；电量读取仍是诊断能力，尚无正式接口。
