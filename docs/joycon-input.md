# Joy-Con 六轴玩法

左右拆下的 Joy-Con 分别驱动 A/B：动作越剧烈，波形值越大，脉冲越密。
这是 NRO 的可选玩法，菜单进入才启用，退出结束；通道强度仍由用户控制。
2026-09-16 用户实机确认左右动作能驱动对应通道，剩余工作是调参和输入细节验证。

## 输入依据与设计

已核对 libnx `switch/services/hid.h` 和官方 `examples/switch/hid/sixaxis`、`sevensixaxis`。
API、类型与读取方式查 headers 和 `nro/source/motion/joycon.c`，不重复字段表。

- 普通掌机六轴来自机身 IMU；SevenSixAxisSensor 是主机＋Joy-Con 的另一套 VR API。
  本玩法暂不映射掌机/Pro 手柄。
- libnx headers 无加速度/角速度/角度的单位注释；社区常见单位不能当已验证事实。
  采样率、硬件量程和原始寄存器未暴露，采样率需从时间/采样序号反推。
- 映射用角速度模长与加速度差分模长，左右镜像轴不影响模长，无需方向标定。
  峰值聚合保留短冲击，死区滞后避免微抖，攻击/释放使起落平滑。
- 25ms 槽位通过 NET_WAVEFORM Append 交给 sysmodule；NRO 不算 App 队列提前量。
  衰减到 0 且静止足够久才停上传，避免截断释放尾巴；全零批次不上传。

玩法在 NRO 而非后台：它需要前台界面反馈，避免常驻 sysmodule 抢 HID；
游戏期间的输入应由另一个事件源设计。纯映射独立在 `motion_feed.c`，可主机测试和快速调参。

## 通道与手柄

2026-09-17 实机发现：插回主机或按同步键关掉后，六轴句柄仍给读数，不能拿读数判连接。
主机设备类型优先、PadState 次之，均无回答才退回读数判断；不可用侧不轮询，不应一边显示未连接一边输出。

两侧句柄必须来自同一次 JoyDual 获取，不按侧反复重取，避免一侧绑到另一只手柄。
一对句柄可用时只用它；单只风格仅在无法取得一对时兜底，不能对同一物理手柄重复 feed。
读数消失后仍要完成释放并复位运动状态；重新扫描按 Y，自动重扫条件以实现为准。

实测一对拆下 Joy-Con 每侧首次轮询 16 条，系统 LIFO 深度 17。
按 60fps 算约 960 条/秒只是估算，稳态采样率/丢失率未统计。
旧记录对插值样本既写过“后续帧有 1~2 条”，又写“抓到的轮询没有”，缺少统一采样窗口；
**不能据此确定出现频率**，需长时间统计。

## 参数与手感

体感、触屏共用 `config/motion.cfg`，由 Advanced 修改并保存。
默认值、步长、范围及关联约束查 `motion_settings.c` 和 `tests/motion/`；缺失/损坏回默认。
死区、量程、权重仅体感用，包络、停发延时、频率、密度、波形上限共用。
固定密度时动作只影响波形值；可变密度时动作越大越密。
通道上限是用户强度的天花板，不是波形上限，A/B 独立，详见 [IPC](ipc.md)。

2026-09-16 实机反馈默认 30ms＋通道强度 50 比 App 自带波形的 40 多偏弱。
“降低间隔、调小量程可能改善”是调参方向，不能当已验证效果；参数页避免每改数都重编。

## 验证入口与待验

主机：`make -C tests/motion`，界面：`make -C tests/canvas`。
实机日志在 `SD:/switch/DGLAB-NX/logs/dglab-net.log`，进入时记录句柄布局，连接变化记录原因。
未轮询与没有读数要分清，新增诊断字段要确认日志缓冲不会截断。

待实机：单位、稳态采样率/采样丢失、插值频率、AtRest 零偏判据、applet 开销/耗电；
检查握持静止的死区、短冲击跟随、释放平滑与归零后停流，再调权重/量程/包络/频率。
蓝牙跨页玩法另按 [BLE 验证](ble-poc.md) 验收，不能沿用 Socket 输出证明。
